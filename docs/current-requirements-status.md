# Code Tweet 現状要件チェック

**作成日**: 2026-05-10
**対象**: 現在の Code Tweet アプリ実装

このドキュメントは、Web アプリとして必要になりやすい要件・仕組みと、現在の Code Tweet で「できていること」「一部できていること」「まだできていないこと」を照らし合わせたメモです。

---

## 1. 全体サマリー

Code Tweet は、MVP として必要な中核機能はかなり揃っています。

特に、以下は実用レベルまで実装済みです。

- プロジェクト説明や GitHub README から X 向け投稿を 5 件生成する
- App Store / GitHub / Web などの URL 種別に応じたリード文を付ける
- ハッシュタグ補完、推奨投稿日時、280 ウェイトチェックを行う
- GitHub ログイン、利用回数制限、残り回数表示を行う
- 公開リポジトリ README の取得と、ログインユーザーのリポジトリ選択 UI がある

一方で、サービスとして正式に有料運用するには、まだ以下が未完了です。

- Stripe 決済
- Customer Portal
- Webhook による Pro プラン自動反映
- 生成履歴の保存
- 投稿予約や X API 連携
- 管理画面、運用監視、問い合わせ導線

## 3. 一部できているところ

| 項目 | 現状 | 足りないこと |
|------|------|--------------|
| Pro プラン | `subscriptions.tier = paid` のユーザーは Pro 扱いできる | Stripe 決済から自動で Pro にする仕組みがない |
| プライベートリポジトリ対応 | paid ユーザーかつ GitHub トークンありなら取得できる設計 | 一般ユーザーが課金して paid になる導線が未実装 |
| GitHub 連携 | GitHub OAuth トークンを保存し、リポジトリ一覧取得に使える | トークン期限切れ・再連携の UX は最低限 |
| 料金ページ | プラン比較は表示できる | Checkout ボタン、決済状態、領収書管理はない |
| 設定ページ | プラン確認、連携状態、削除導線がある | 支払い管理、請求履歴、プラン変更は未実装 |
| エラー表示 | 主要エラーは表示できる | エラーの記録・集計・運用通知は未実装 |
| ドキュメント | README、要件定義、履歴ドキュメントがある | 現状との差分が増えやすいので定期更新が必要 |

## 7. まずの結論

現在の Code Tweet は「生成ツールとして使える状態」には到達しています。

次の大きな分岐は、以下のどちらを優先するかです。

1. **収益化を進める**
   Stripe 導入、Pro プラン反映、支払い管理を作る。

2. **プロダクト品質を固める**
   生成整形のテスト、生成履歴、エラー監視、規約整備を進める。

現状のアプリに一番足りない「仕組み」は、課金と運用です。
中核機能はできているので、次は「継続して安心して使ってもらうための周辺機能」を足していく段階です。
