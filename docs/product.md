# Code Tweet プロダクト概要

最終更新: 2026-08-03

## 目的

Code Tweet は、README やプロジェクト説明から次の3つを AI で生成する個人開発者向け Web アプリです。

- **Code Tweet**: X 向けのマーケティングポスト 5 件（紹介、使い方、ユースケース、共感、CTA の流れ、推奨投稿日時と理由付き）
- **note Draft**: note.com に貼り付けられる Markdown 記事の下書き 1 本
- **App SS**: App Store 提出用スクリーンショット（見出しコピー・レイアウト・配色）の一括生成

## 対象ユーザー

主対象は、個人開発アプリや小規模サービスを継続的に発信したい開発者です。副対象は、発信を始めたい開発者、複数プロダクトを運営する個人、README をもとに告知文やストア掲載素材を素早く作りたい人です。

## 現在の主要機能

### Code Tweet / note Draft

- GitHub リポジトリ URL から README を取得
- README や機能説明の直接入力
- 口調メモ、投稿に載せる URL、ハッシュタグの任意指定
- Gemini API `gemini-2.5-flash` による 5 件生成（note Draft は Markdown 1 本）
- Code Tweet は 8 言語で生成可能。生成結果の下から言語を追加でき、翻訳ではなく同じ README から対象言語で書き直す（言い回しと 280 weighted length を言語ごとに最適化）。1 リクエスト = 1 言語で、クレジットは 4 言語ごとに 1 回分を消費（切り上げ）
- `twitter-text` による X の 280 weighted length チェックと自動短縮
- 生成ポストの「Xで投稿」ボタン（X Web Intent / 共有リンク。API・課金不要、ログイン不要）

### App SS（App Store スクリーンショット生成）

- GitHub リポジトリ URL または README 直接入力から、見出しコピー・強調ワード・推奨レイアウトを Gemini が一括生成
- 見出しコピーの生成言語を 8 言語から選択可能。選んだ言語の文字体系に合うフォント（Noto Sans/Serif SC・TC・KR）へ自動で切り替わる。1 デッキ 1 言語で、言語は `AppSSProject.locale` が持つ
- 配色テーマ 11 種・背景装飾 5 種を AI が自動選択、またはアプリ専用の配色パレットをそのつど新規生成（`customTheme`）
- スライドレイアウトはヒーロー・デバイス上/下・2台重ね・コラージュ（2枚 `collage-duo` / 3枚 `collage-trio`）・見出しのみの7種
- Apple 公式 Product Bezel（iPhone）を使ったデバイスフレーム。フォントは日本語 9 種（ゴシック・丸ゴ・明朝・角ゴ・デラゴシック・しっぽり明朝・クレー・ロックンロール・M PLUS Rounded）＋ 簡体字・繁体字・韓国語の Noto Sans/Serif 各 2 種の計 15 種
- README 読み込み時に `/api/appss/extract-info` がアプリ名・説明・主な機能を推定してフォームへ自動入力する（AI 呼び出しはあるが補助機能のため無料・回数消費なし）
- 取り込んだスクショ画像はブラウザの IndexedDB にのみ保存し、サーバーへは送信しない
- App Store 必須サイズ（6.9 / 6.5 / 6.3 / 6.1 インチ）を PNG で一括書き出し（zip化含めクライアント側で完結）
- 透かし入り書き出し・エディタ編集は無料無制限。透かしを外した書き出しのみ生成回数を1回消費（`/api/appss/export-unlock`、AI 呼び出しなしの gating 専用エンドポイント）

### 共通機能

- UI の 8 言語対応（日本語 / 英語 / スペイン語 / 簡体字中国語 / 繁体字中国語 / フランス語 / ドイツ語 / 韓国語）。日本語は接頭辞なしの現行 URL、他言語は `/en/...` のようにパスが生える（`localePrefix: "as-needed"`）
- GitHub OAuth ログイン、公開リポジトリ一覧選択
- クレジット購入者向けのプライベートリポジトリ対応（旧 Pro 特典を継承）
- クレジット購入者向けの生成履歴保存（Code Tweet の生成結果を最新 50 件、上限超過分は自動削除）と個別削除
- Stripe Checkout（クレジットパック） / Webhook / Customer Portal
- 管理画面で利用状況、プラン変更、ゲスト利用回数リセットを操作
- `/about`、`/about/appss`、`/pricing`、`/terms`、`/privacy`、`/contact` を提供

## プランと制限

| 区分 | 生成回数 | README 文字数 | リポジトリ |
|---|---:|---:|---|
| ゲスト | 3 回まで | 1,000 文字 | 公開リポジトリ |
| 無料ログイン | 月 3 回 | 1,000 文字 | 公開リポジトリ、一覧選択 |
| クレジット購入者 | 月 3 回 + 購入クレジット | 10,000 文字 | 公開・非公開リポジトリ |

クレジットパックは単発課金（10回 ¥100 / 30回 ¥300 / 50回 ¥500 / 100回 ¥700、定義は `src/lib/creditPacks.ts`）。生成回数は Code Tweet・note Draft・App SS（コピー生成・透かし解除書き出し）で共有プールとして合算カウントされます。ログインユーザーの無料枠は月初にリセットされます。ゲスト利用は IP ハッシュ単位の累計です。旧 Pro サブスク（月額 500 円・月 30 回）は新規販売を停止し、既存契約者のみ継続しています。

入力補助フィールドの上限は、追加プロンプト 100 文字、URL 500 文字、ハッシュタグ 100 文字です（App SS はアプリ説明 10,000 文字、機能・特徴は 8 件まで）。GitHub README 取得には極端なペイロードを防ぐ 64 KiB の粗い保護もあります。

## データと保存方針

- README 本文と追加プロンプト本文は保存しない
- クレジット購入者・旧 Pro 契約者の生成履歴には生成結果、source URL、ハッシュタグ、作成日時を保存する。保存上限は 1 ユーザーあたり最新 50 件で、新規追加時に超過分を同期的に削除する
- App SS のスクショ画像はブラウザの IndexedDB にのみ保存し、サーバーへは送信しない。PNG合成・zip化もすべてクライアント側で行う
- GitHub OAuth token / PAT は `GITHUB_PAT_ENCRYPTION_KEY` で AES-256-GCM 暗号化して保存し、リポジトリ一覧取得や非公開 README 取得に使う
- 利用回数は Supabase の `usage_logs` と `ip_usage_logs` で管理する
- アカウント削除時は関連データも削除する

## 事業とKPI

北極星指標は課金転換（クレジットパック購入・旧 Pro 契約継続）です。限界費用（Gemini API + Stripe 手数料）は売上に対して小さく、粗利率は高水準です。価格の制約は固定費（インフラ）で、Vercel/Supabase を無料枠で運用すれば実質 1 人目から黒字です。App SS の透かし解除書き出しは AI 呼び出しを伴わないため限界費用はほぼゼロです。短期目標は月間課金者 10 人相当（旧 Pro 換算）。

| KPI | 2026-10 目標 |
|---|---:|
| 課金者数（旧 Pro + クレジット購入者） | 10 人 |
| ログインユーザー累計 | 200 人 |
| MAU | 1,000 |
| 月間生成回数（Code Tweet + note Draft + App SS） | 5,000 |
| 無料から課金への転換率 | 5% |
| 月次解約率（旧 Pro 契約者） | 10% 未満 |

## リスク

| リスク | 対応 |
|---|---|
| AI の誤情報 | 投稿前確認の案内を維持し、プロンプト改善を継続 |
| Gemini API 料金高騰 | 月次生成回数の上限を維持し、必要に応じて制限を再計算 |
| Stripe 本番エラー | Webhook と Supabase `subscriptions` / `credit_grants` を突き合わせる |
| 一人運営のキャパ超過 | 新機能より計測、告知、軽微な改善を優先 |
| リポジトリ可視性の誤変更 | Code Tweet リポジトリは Private 維持 |
| App SS の透かし解除課金の回避 | クレジット消費は `/api/appss/export-unlock` のサーバー側チェックで行うが、PNG 生成自体が完全にクライアント側のため、DevTools から透かし無しの書き出しを直接呼ぶ迂回は技術的に防げない。サーバー描画への移行はコスト構造（限界費用ほぼゼロ）を壊すので採らず、軽度の迂回は許容する経営判断とする |
