# Code Tweet プロダクト概要

最終更新: 2026-05-24

## 目的

Code Tweet は、README やプロジェクト説明から X 向けのマーケティングポストを 5 件生成する個人開発者向け Web アプリです。紹介、使い方、ユースケース、共感、CTA の流れで投稿案を作り、推奨投稿日時と理由も付けます。

## 対象ユーザー

主対象は、個人開発アプリや小規模サービスを継続的に発信したい開発者です。副対象は、発信を始めたい開発者、複数プロダクトを運営する個人、README をもとに告知文を素早く作りたい人です。

## 現在の主要機能

- GitHub リポジトリ URL から README を取得
- README や機能説明の直接入力
- 口調メモ、投稿に載せる URL、ハッシュタグの任意指定
- Gemini API `gemini-2.5-flash` による 5 件生成
- `twitter-text` による X の 280 weighted length チェックと自動短縮
- GitHub OAuth ログイン、公開リポジトリ一覧選択
- Pro ユーザー向けのプライベートリポジトリ対応
- Pro ユーザー向けの生成履歴保存（最新 50 件、上限超過分は自動削除）と個別削除
- Stripe Checkout / Webhook / Customer Portal
- 管理画面で利用状況、プラン変更、ゲスト利用回数リセットを操作
- `/about`、`/pricing`、`/terms`、`/privacy`、`/contact` を提供

## プランと制限

| 区分 | 生成回数 | README 文字数 | リポジトリ |
|---|---:|---:|---|
| ゲスト | 3 回まで | 1,000 文字 | 公開リポジトリ |
| 無料ログイン | 月 3 回 | 1,000 文字 | 公開リポジトリ、一覧選択 |
| Pro | 月 30 回 | 10,000 文字 | 公開・非公開リポジトリ |

Pro は月額 980 円。ログインユーザーの生成回数は月初にリセットされます。ゲスト利用は IP ハッシュ単位の累計です。

入力補助フィールドの上限は、追加プロンプト 100 文字、URL 500 文字、ハッシュタグ 100 文字です。GitHub README 取得には極端なペイロードを防ぐ 64 KiB の粗い保護もあります。

## データと保存方針

- README 本文と追加プロンプト本文は保存しない
- Pro ユーザーの生成履歴には生成結果、source URL、ハッシュタグ、作成日時を保存する。保存上限は 1 ユーザーあたり最新 50 件で、新規追加時に超過分を同期的に削除する
- GitHub OAuth token / PAT は `GITHUB_PAT_ENCRYPTION_KEY` で AES-256-GCM 暗号化して保存し、リポジトリ一覧取得や Pro の非公開 README 取得に使う
- 利用回数は Supabase の `usage_logs` と `ip_usage_logs` で管理する
- アカウント削除時は関連データも削除する

## 事業とKPI

北極星指標は Pro 課金者数です。損益分岐の目安は Pro 9 人前後、短期目標は Pro 10 人です。

| KPI | 2026-10 目標 |
|---|---:|
| Pro 課金者数 | 10 人 |
| ログインユーザー累計 | 200 人 |
| MAU | 1,000 |
| 月間生成回数 | 5,000 |
| 無料から Pro への転換率 | 5% |
| 月次解約率 | 10% 未満 |

## 今後の候補

- `/admin` の課金ファネル指標追加

- 履歴検索またはお気に入り。需要が見えた場合に片方だけ追加
- Instagram / Threads 対応や上位プランは Pro 10 人到達後に再検討

## リスク

| リスク | 対応 |
|---|---|
| AI の誤情報 | 投稿前確認の案内を維持し、プロンプト改善を継続 |
| Gemini API 料金高騰 | Pro 上限 30 回を維持し、必要に応じて制限を再計算 |
| Stripe 本番エラー | Webhook と Supabase `subscriptions` を突き合わせる |
| 一人運営のキャパ超過 | 新機能より計測、告知、軽微な改善を優先 |
| リポジトリ可視性の誤変更 | Code Tweet リポジトリは Private 維持 |
