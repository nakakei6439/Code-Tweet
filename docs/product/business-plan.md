# Code Tweet 事業計画書

**作成日**: 2026-05-05
**対象バージョン**: V8 Phase A.5 着手時点

---

## 1. ミッション

**「個人開発者が自分のプロダクトを継続的に発信できる仕組みを提供する」**

個人開発者の最大の障壁は「作って終わり」になること。マーケティングが続かず、せっかく作ったプロダクトが使われない。Code Tweet は **README からポストを自動生成**することでこの障壁を取り除く。

---

## 2. 市場分析

### 2.1 市場規模（日本国内）

| セグメント | 概算規模 | 根拠 |
|-----------|---------|------|
| 日本の個人開発者（X 運用中） | 1〜2 万人 | Zenn 月次 PV から推定・X #個人開発タグの活発な投稿者数 |
| 主ターゲット A（週 5〜10 回ポスト） | 数千人 | 上記のうち継続発信層 |
| 副ターゲット B（複数プロダクト運営） | 数百人 | catnose / makitar 等の層 |

### 2.2 競合

| 競合 | 提供価値 | 価格 | 差別化ポイント |
|------|---------|------|--------------|
| **Hootsuite / Tweet Hunter** | 汎用 SNS 投稿管理 | $20〜$200/月 | テキスト手入力。GitHub 連携なし。英語 |
| **Typefully / Postwise** | AI ポスト生成 | $25〜$99/月 | 個人開発特化ではない |
| **AiToEarn / Probot Twitter** | GitHub Issue 連動投稿 | OSS | 機能限定的・README ベースではない |

**Code Tweet の差別化**：
1. **README から直接生成**：他はテキスト手入力
2. **個人開発特化のプロンプト**：紹介→使い方→ユースケース→共感→CTA の 5 段アーク
3. **日本語特化**：競合はほぼ英語
4. **月額 980 円**：競合の 1/3〜1/10
5. **プライベートリポ対応**（Pro）：開発中プロダクトの告知準備にも使える

## 3. ターゲット顧客

### Primary：毎週コンスタントに X でポストする個人開発者

- 30〜40 代男性中心、技術職
- Zenn / Qiita / 個人ブログでの発信経験あり
- 1〜2 個のプロダクトを継続運営
- 月 1,000 円以内なら課金抵抗が低い

### Secondary：これから発信を始めたい開発者

- 無料枠で価値検証 → Pro へアップグレード

### Tertiary：複数プロダクト運営者

- 月 100 回上限が刺さる層
- 価格弾力性が低く、上位プランがあれば追加で取れる可能性（V9 以降検討）

## 4. 価値提案

| ペイン | Code Tweet の解決策 |
|--------|-------------------|
| 毎日ネタを考えるのが大変 | README から自動生成 |
| 文章が思いつかない | 5 段アーク + トーン指示 |
| いつ投稿すればいいかわからない | 推奨投稿日時を AI が提案 |
| 文字数オーバー | 自動短縮（最大 4 回試行） |
| 開発中プロダクトも告知したい | Pro でプライベートリポ対応 |

## 5. 収益モデル（フリーミアム）

### 5.1 プラン構造（V8 Phase B 以降アクティブ化）

| プラン | 月額 | 月間生成回数 | 主要機能 |
|--------|------|------------|---------|
| ゲスト | ¥0 | 3 | 公開リポジトリのみ |
| 無料 | ¥0 | 10 | 公開リポジトリのみ + 公開リポ一覧（GitHub 連携時） |
| **Pro** | **¥980** | **100** | プライベートリポ対応 + 全リポ一覧（公開＋非公開） |

### 5.2 課金導線

1. **ゲスト → 無料**：上限 3 回到達時に「GitHub ログイン」CTA
2. **無料 → Pro**：上限 10 回到達時に「Pro プランへ」CTA → `/pricing` → Stripe Checkout
3. **Pro 維持**：月初リセット時にメール送信（V9+ で検討）

### 5.3 収益試算

| 想定 | 月間アクティブ無料 | Pro 課金率 | Pro ユーザー数 | 月商（税抜） |
|------|-----------------|-----------|--------------|------------|
| 控えめ | 100 人 | 5% | 5 人 | ¥4,900 |
| 標準 | 500 人 | 5% | 25 人 | ¥24,500 |
| 強気 | 2,000 人 | 7% | 140 人 | ¥137,200 |

サブスク事業の課金率の業界目安：2〜10%。個人開発特化なので 5% を中央値に置く。

## 6. コスト構造

### 6.1 月額コスト試算（Pro 100 人想定）

| 費目 | 月額 | 備考 |
|------|------|------|
| Gemini API（Flash） | 〜¥3,000 | 100 人 × 月 100 回 = 1 万生成。Flash 単価 ¥0.3 / 生成想定 |
| Supabase（Pro） | $25 = ¥3,800 | DB + Auth + Storage |
| Vercel（Pro） | $20 = ¥3,000 | ホスティング |
| Stripe 手数料 | ¥3,800 | 980 × 100 × 3.6%（決済手数料）+ 固定費 |
| ドメイン | 〜¥150 | 年間で按分 |
| **合計** | **約 ¥13,800** | |

### 6.2 損益分岐点

- Pro 1 人あたり粗利：¥980 - ¥138（変動費按分）= 約 ¥842
- 固定費（Supabase / Vercel / ドメイン）= 約 ¥7,000 / 月
- **損益分岐：Pro 約 9 人**

→ Pro 10 人で黒字化。100 人到達なら月利 約 ¥80,000。

## 7. KPI

### 7.1 ダッシュボード化したい指標

| KPI | 計測方法 | 目標（6 ヶ月後） |
|-----|---------|--------------|
| MAU（ゲスト含む） | `ip_usage_logs` + `usage_logs` の月次ユニーク | 1,000 |
| ログインユーザー数 | `auth.users` の累計 | 200 |
| Pro 課金者数 | `subscriptions.tier='paid'` | 10 |
| 課金率 | Pro / ログインユーザー | 5% |
| 月間生成回数 | `usage_logs` 合計 | 5,000 |
| 解約率（Phase B 以降） | Stripe `customer.subscription.deleted` | < 10% / 月 |

### 7.2 観測ポイント

- ユーザーが「上限到達」した割合 → 高ければ無料枠が小さい兆候
- Pro ユーザーの月間生成回数の中央値 → 100 に張り付くなら上位プラン要検討

## 9. リスクと対策

| リスク | 影響 | 対策 |
|--------|------|------|
| Gemini API 料金高騰 | 利益率悪化 | コスト連動の上限見直し・キャッシュ導入検討 |
| 競合の参入 | 市場シェア低下 | 個人開発特化を強める・コミュニティ作り |
| Stripe 規約変更（個人事業主） | 決済停止 | 個人事業主開業届を先に出しておく |
| AI ハルシネーション | 誤情報投稿 | プロンプト改善・ユーザーが必ず内容確認する設計（コピー前にレビュー） |
| 無料ユーザーの API 悪用 | コスト爆発 | 月単位制限済（Phase A）+ レートリミット強化（必要時） |
| ターゲット A の母数が想定より小さい | 課金者が伸びない | Secondary（初心者）への訴求を強める・ペルソナ広げる |
