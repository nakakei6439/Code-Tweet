# Webアプリの作り方：初心者向けガイド

> はじめてWebアプリを作る方向けに、難しい言葉をなるべく使わずに説明します。

---

## まず知っておきたい基礎知識

Webアプリは大きく3つの部品でできています。

| 部品 | 別名 | 役割 | 例え |
|------|------|------|------|
| フロントエンド | 画面（UI） | ユーザーが見て触る部分 | お店の店頭・ショーウィンドウ |
| バックエンド | サーバー | 裏側で計算・処理をする部分 | お店の倉庫・バックオフィス |
| データベース | DB | データを保存する場所 | 帳簿・ファイルキャビネット |

この3つをつなぎ合わせることで、Webアプリが動きます。

---

## STEP 1: 作るものを決める（企画）

まず「何を作るか」を言葉にしましょう。コードを書く前の一番大事なステップです。

**考えること：**
- **誰のため？**（例：料理が好きな人、勉強したい学生など）
- **何ができるアプリ？**（例：レシピを投稿・検索できる）
- **絶対に必要な機能は何？**（例：投稿する、一覧を見る、削除する）

**ポイント：** 機能を欲張りすぎず、最初は「これだけあれば使える」という最小限の機能から始めましょう。

### 将来追加したい機能もリストアップしておこう（機能ロードマップ）

最初に全部作ろうとしなくて大丈夫です。「V1 で動くものを出して、あとから少しずつ足す」のが正解です。
ただし、**将来何を追加したいかを最初にリストアップ**しておくと、設計のときに見通しが立てやすくなります。

**Code Tweet の例：**

| バージョン | 追加する機能 | 使う外部サービス | なぜこの順番？ |
|-----------|------------|----------------|-------------|
| V1 | テキスト貼り付け → ツイート生成 | Gemini API | まず「動くもの」を作って公開する |
| V2 | GitHub URL からコードを自動取得 | GitHub API | 手で貼り付ける手間をなくす（UX 改善） |
| V3 | 生成したツイートを保存できる | Supabase（DB） | 使い続けてもらうための履歴機能 |
| V4 | スケジュール管理（投稿日時を設定） | なし | 保存できてから初めて意味を持つ |
| V5 | Claude API も選択可能に | Claude API | AI の選択肢を広げてユーザーを増やす |
| V6 | ログイン機能（Google 認証） | Supabase Auth | 誰のデータかを区別するために必要 |
| V7 | 広告の実装（Google AdSense） | AdSense | ユーザーが集まってから収益化する |
| V8 | フリーミアム導入（月額プラン） | Stripe | 広告の次のステップとして課金を追加 |
| V9 | Instagram・Threads など他 SNS 対応 | なし | ユーザーから「欲しい」と言われたら |

> **初心者向けポイント：**
> - V3（保存）→ V6（ログイン）の順番に注目。「誰が保存したか」を管理するにはログインが必要なので、保存機能を先に作ってからログインを追加する、という順番には理由があります。
> - V7（広告）→ V8（課金）の順番も同様。まず広告で収益化の実績を作ってから、サブスクへ移行するのが自然な流れです。

## STEP 2: 設計図を描く（設計）

家を建てる前に間取り図を描くように、アプリも先に設計図を描きます。

### 画面の設計図（ワイヤーフレーム）
- 紙やホワイトボードに「どんな画面があるか」をラフに描く
- 無料ツール：**Figma**（https://figma.com）がおすすめ
- 「ログイン画面」「一覧画面」「詳細画面」など、必要な画面を洗い出す

### データの設計
- アプリで「何を保存するか」をリストアップする
- 例：ユーザー情報（名前・メールアドレス）、投稿（タイトル・本文・日付）

## STEP 3: 使う技術を選ぶ

初心者には以下の組み合わせがおすすめです。選択肢が多くて迷ったら、まずこれで始めましょう。

| 役割 | おすすめ | 理由 |
|------|---------|------|
| フロントエンド（画面） | **Next.js** | 日本語情報が多く、学習リソースが豊富 |
| データベース（データ保存） | **Supabase** | 設定がかんたん、無料プランあり |
| 公開（ホスティング） | **Vercel** | GitHubと連携でかんたんに公開できる |

> **慣れてきたら：** 他のフレームワークや言語（Python、Ruby など）にも挑戦してみましょう。

---

## STEP 4: 開発環境を準備する

コードを書く前に、パソコンに必要なツールをインストールします。

### 最低限インストールするもの

1. **VS Code**（コードエディタ）
   - コードを書くためのアプリ。無料で使えます
   - ダウンロード：https://code.visualstudio.com

2. **Node.js**
   - Next.jsを動かすために必要
   - ダウンロード：https://nodejs.org（「LTS版」を選ぶ）

3. **Git**（バージョン管理ツール）
   - ファイルの変更履歴を記録するツール。「セーブデータ」のようなもの
   - ダウンロード：https://git-scm.com

### プロジェクトを作成するコマンド

ターミナル（Macはターミナル、WindowsはPowerShell）を開いて以下を入力：

```bash
# Next.jsのプロジェクトを新規作成する
npx create-next-app@latest my-app

# 作ったフォルダに移動する
cd my-app

# アプリを起動して確認する
npm run dev
```

ブラウザで `http://localhost:3000` を開くと、アプリが動いているのが確認できます。

## STEP 5: コードを書く（実装）

いよいよコードを書いていきます。次の順番で進めると混乱しにくいです。

### おすすめの順番

```
① まずデータを保存できるようにする（データベース）
    ↓
② 画面を作る（フロントエンド）
    ↓
③ 画面とデータをつなぐ
    ↓
④ ログイン機能を追加する（必要な場合）
```

### 作りながらのコツ
- **こまめに保存・確認する**：少し書いたらブラウザで動作確認する習慣をつけましょう
- **エラーが出ても焦らない**：エラーメッセージをそのままコピーして検索すると解決策が見つかることが多いです
- **完璧を目指さない**：まず動くものを作ることを優先しましょう

---

## STEP 6: 動作確認する（テスト）

公開する前に、アプリが正しく動くか確認します。

### 最初はこれだけでOK（手動テスト）
- 実際にブラウザで操作して、意図通りに動くか確認する
- いろんなパターンを試す（正常な操作・変な入力・エラーが出そうな操作）

> **慣れてきたら：** 自動テスト（テストコードを書くと毎回自動で確認してくれる仕組み）に挑戦してみましょう。

---

## STEP 7: インターネットに公開する（デプロイ）

作ったアプリを世界中からアクセスできるようにします。

### Vercelを使った公開手順（おすすめ）

1. **GitHubにコードをアップロードする**
   - GitHubは無料で使えるコードの保管場所です（https://github.com）

2. **Vercelにサインアップする**（https://vercel.com）

3. **GitHubのリポジトリを選んで「Deploy」ボタンを押す**
   - これだけで公開完了！URLが発行されます

4. **（任意）独自のドメイン（URLの名前）を設定する**
   - 例：`https://my-app.vercel.app` → `https://my-cool-app.com`

> **慣れてきたら：** コードをGitHubにプッシュするたびに自動で公開される仕組み（CI/CD）も調べてみましょう。

## STEP 8: 使いながら育てる（運用・改善）

公開してからが本番です。使いながら少しずつ良くしていきましょう。

- **使ってもらう**：友人や知人に使ってもらいフィードバックをもらう
- **バグを直す**：問題が見つかったら修正する
- **機能を追加する**：ユーザーの声をもとに新しい機能を足していく

STEP 8 はゴールではなく、**ここからが本当のスタート**です。STEP 1 で作ったロードマップに沿って、V2・V3 と順番に機能を追加していきましょう。

**Code Tweet の次のステップ（V2 以降）：**

| バージョン | 追加する機能 |
|-----------|------------|
| **V2** | GitHub URL からコードを自動取得（現在進行中） |
| V3 | 生成したツイートを保存できる |
| V4 | スケジュール管理（投稿日時を設定） |
| V5 | Claude API も選択可能に |
| V6 | ログイン機能（Google 認証） |
| V7 | 広告の実装（Google AdSense） |
| V8 | フリーミアム導入（月額プラン） |
| V9 | Instagram・Threads など他 SNS 対応 |

> V2 の詳細タスクは [`step6-v2-todo.md`](./step6-v2-todo.md) にまとめています。

## 全体の流れまとめ

```
STEP 1: 作るものを決める（企画）
    ↓
STEP 2: 設計図を描く（設計）
    ↓
STEP 3: 使う技術を選ぶ
    ↓
STEP 4: 開発環境を準備する
    ↓
STEP 5: コードを書く（実装）
    ↓
STEP 6: 動作確認する（テスト）
    ↓
STEP 7: インターネットに公開する（デプロイ）
    ↓
STEP 8: 使いながら育てる（運用・改善） ← ここを繰り返す
```

## 困ったときの調べ方

- **エラーメッセージ**はそのままコピーしてGoogle検索する
- **Zenn**（https://zenn.dev）：日本語の技術記事が多く初心者向け
- **YouTube**：「Next.js 入門」などで検索すると動画チュートリアルが見つかる
- **ChatGPT / Claude**：コードの書き方やエラーの意味を質問できる

> **一番大切なこと：** 最初から完璧なアプリを作ろうとしなくて大丈夫です。
> まず動くものを作って公開することが、上達への一番の近道です！
