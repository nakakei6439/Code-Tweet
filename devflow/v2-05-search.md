# Feature 5: 検索・フィルタ

← [概要に戻る](./v2-00-overview.md)

**前提**: Feature 4（ポスト保存・履歴）が完了していること

---

## 目的

保存件数が増えてきたときに、特定のプロジェクトのポストを素早く探せるようにする。
保存件数が少ないうちは価値が低いため、Feature 4 完了後に着手する。

---

## タスク

- [ ] `/history` ページに検索ボックスを追加
- [ ] タイトル・ポストテキストで絞り込む（まずはクライアントサイドフィルタで実装）
- [ ] （将来）保存件数が数百件を超えたら Supabase の `ILIKE` クエリまたは `pg_trgm` 全文検索へ移行

---

## 実装方針

### フェーズ 1（最初）：クライアントサイドフィルタ

- 全データを取得済みの状態で JavaScript でフィルタリング
- 件数が少ないうちはこれで十分、サーバーへの追加リクエスト不要
- 実装コスト：低

### フェーズ 2（将来）：サーバーサイド検索

- 件数増加後に移行
- Supabase のクエリ例：
  ```sql
  SELECT * FROM tweet_sets
  WHERE user_id = auth.uid()
    AND (title ILIKE '%検索ワード%'
      OR tweets::text ILIKE '%検索ワード%')
  ORDER BY created_at DESC;
  ```
